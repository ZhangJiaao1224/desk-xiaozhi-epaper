# 到货当天验证清单

原则：一次只验一件事，验不过就停下来查，不要连着往下做。

## 第 0 步：开箱记录（10 分钟）

- [ ] 拍开发板正反面照片，对照卖家给的引脚图，把 `hardware/引脚记录表.md` 填满。
- [ ] 确认板载 codec 型号与板载 OLED（分辨率、I2C 地址），OLED 是主显示，必须先确认。
- [ ] 墨水屏背面丝印拍照，确认驱动 IC 是 SSD1683、400x300、单色。
- [ ] 确认墨水屏配套驱动板是 8 针还是 24 针 FPC，找齐杜邦线。

**卡住就停**：引脚表填不满，后面一律不做。

## 第 1 步：点亮墨水屏（用极小工程，不碰小智）

目的：把屏幕和接线单独验掉，出问题时不用怀疑是小智的锅。

- [ ] 按引脚表接线，墨水屏单独供电 3.3V，先只接 SPI + DC/RST/BUSY/CS。
- [ ] 烧点亮工程，观察全刷是否正常显示测试图。
- [ ] 记实测耗时：全刷多久、局刷多久（用串口打时间戳），和设计文档里的 1200ms / 400ms 对一下。
- [ ] 验局刷：局部改一小块，看是否正确变化、有无残影。
- [ ] 验连续局刷 20 次后的残影程度，决定全刷间隔。

**验收**：能全刷、能局刷、无明显花屏。做不到就贴串口日志，先查 SPI 模式和 BUSY 极性。

## 第 2 步：编自定义板型固件

- [ ] 填 `config.h`：I2S、I2C、PA、墨水屏 SPI、按键，全部来自引脚表。
- [ ] `config.json` 里板型标识必须唯一（例如 `desk-epaper-<你的名字>`），不许用官方标识。
- [ ] 编译，先不烧，确认能出 `build/merged-binary.bin`。
- [ ] 烧录，看串口日志有没有报错。

**验收**：串口无 ESP_ERROR，墨水屏上出现小智的待机界面。

## 第 3 步：配网与对话

- [ ] 上电后手机连 `Xiaozhi-xxxx` 热点，浏览器进配网页，填 **2.4G** WiFi 密码（5G 和网页认证网络连不上）。
- [ ] 设备显示 6 位验证码，去 xiaozhi.me 注册登录、添加设备、输验证码绑定。
- [ ] 控制台里选大模型，填 DeepSeek 或通义千问的 API Key。
- [ ] **关掉 OTA 自动升级**，防止自定义固件被官方固件覆盖。
- [ ] 喊"小智小智"对话，确认能听到回复。

**验收**：能对话。到这一步语音链路就算通了。

## 第 4 步：验双屏分工

- [ ] 对话几轮，确认 OLED 上的状态和表情刷新及时，不发卡。
- [ ] 确认墨水屏在对话期间不被高频刷新（它是日历看板，不该追动画）。
- [ ] 让日历跨过一分钟，确认墨水屏一分钟只刷一次。
- [ ] 连续跑够 60 次局刷，观察残影，再决定全刷间隔。

**验收**：对话流畅；墨水屏每分钟稳定刷一次且无明显残影。

## 第 5 步：日历与联动

- [ ] 日历页显示时间 / 日期 / 星期 / 喝水杯数。
- [ ] SNTP 对时成功，时间正确。
- [ ] 每分钟更新一次，观察一分钟是否只刷一次。
- [ ] 到点播报喝水。
- [ ] 说"我喝了一杯"，杯数 +1 且刷屏。

## 每次改动都要记

改完一个功能就写清楚：改了哪几个文件、怎么烧录、怎么验证、实测结果。
没注释的代码不许提交。
