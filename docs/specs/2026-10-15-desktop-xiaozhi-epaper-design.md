# 桌面小智 + 墨水屏日历 设计文档

日期：2026-10-15
状态：待评审
适用硬件：ESP32-S3 N16R8（板型待卖家确认）+ 4.2 寸 400x300 单色墨水屏（SSD1683）

## 1. 目标与非目标

目标：一块桌面设备能做到三件事，做完能停下来玩几天。

1. 喊"小智小智"能对话（语音链路走 xiaozhi.me 官方云）。
2. 墨水屏常驻显示时间 / 日期 / 星期 / 喝水进度。
3. 到点播报喝水，语音说"我喝了一杯"能记杯数并刷新屏幕。

非目标：不做产品、不发版、不上 Home Assistant、不跑本地大模型、不在 ESP32 上跑视觉。

## 2. 已核实的关键事实

以下几条是查过源码和库之后确认的，不是推测。

| 事实 | 依据 |
|---|---|
| 上游要求 ESP-IDF >= 6.0.1，推荐 6.1，不支持 5.x | `xiaozhi-esp32` v2.5.2 `README_zh.md` |
| 上游预编译固件按板型编译，共 171 个变体 | 同上 |
| 上游已有 EPD 驱动，但只有 2.9 寸 128x296 一种实现，仅 `maza-ai` 两块板使用 | `main/display/epd_display/` |
| 4.2 寸 400x300 SSD1683 有现成参考时序 | GxEPD2 `src/gdey/GxEPD2_420_GDEY042T81.cpp` |
| 该面板支持局刷；局刷约 400ms，全刷约 1200ms | `GxEPD2_420_GDEY042T81.h` 常量 |
| 该面板不发 `0x32` 写 LUT，使用面板内置 OTP 波形 | `GxEPD2_420_GDEY042T81.cpp` |

## 3. 为什么必须自编译固件

上游预编译的 `merged-binary.bin` 把板级配置和显示驱动一起编进了二进制，官方变体里
不存在"本板 + 4.2 寸 SSD1683"的组合。所以：

- 刷预编译固件只能验证板子和语音链路，一旦要接墨水屏就必须自编译，那一次刷机基本白做。
- 自编译时**必须新建独立板型标识**，不能覆盖官方板型。否则 OTA 会把这个设备当成官方板型，
  用官方固件把它覆盖回去。

结论：直接走自编译路线，跳过"先刷官方固件"这一步。板子好坏可以在自编译固件上验证。

## 4. 架构

### 4.1 硬件链路

```
ESP32-S3 N16R8
  ├─ 板载音频 codec + 麦克风 + 功放   (I2S / I2C，引脚待确认)
  ├─ 4.2" 墨水屏 SSD1683 400x300      (SPI，引脚待确认)
  ├─ BOOT 按键                        (配网 / 打断对话)
  └─ WiFi 2.4G
        │  WSS
        ▼
  xiaozhi.me 官方服务端  ──HTTP──▶  DeepSeek / 通义千问
```

### 4.2 软件分层

在 `xiaozhi-esp32` 源码树上新增三块内容，其余官方代码不动。

```
main/boards/<我们的板型>/
    config.h                板级引脚与参数（等卖家原理图后填）
    config.json             板型上报标识（必须唯一，防 OTA 覆盖）
    <board>.cc              板级初始化：I2C / SPI / 显示 / 按键 / codec

main/display/epd_gdey042t81/
    epd_gdey042t81.{h,cc}   纯 SSD1683 时序驱动，不依赖 LVGL
    epd_display_lvgl.{h,cc} 把驱动包成小智的 Display 接口 + 刷新节流
```

驱动拆成两层是为了让 `epd_gdey042t81` 能脱离小智单独测试——到货当天先用一个极小的
IDF 工程点亮屏幕，确认接线和刷新参数，再编进小智固件。两层复用同一份驱动源文件，
不做复制粘贴。

### 4.3 显示定位

墨水屏当小智的**主显示**，日历是它的一个 LVGL 页面。理由：上游 `EpdDisplay` 本来就是
`LcdDisplay` 的子类，走这条路不用先知道板载有没有 OLED，也不用维护第二块屏。

页面切换策略：

| 设备状态 | 墨水屏显示 |
|---|---|
| 待机超过 N 秒（默认 30s） | 日历页（时间 / 日期 / 星期 / 喝水杯数） |
| 唤醒、对话中 | 对话页（官方 UI），但**对话中冻结刷屏** |
| 对话结束 | 停留对话页几秒，然后回日历页并刷一次 |

## 5. 刷新策略（本项目最关键的设计）

问题：SSD1683 局刷一次约 400ms，而 LVGL 用整屏 FULL 渲染，每帧都会触发一次 flush。
无节流的话对话表情动画会把刷屏队列堵死，画面严重滞后且残影堆积。

四条策略一起用：

1. **节流**：flush 回调记录时间戳，距上次刷屏不足 `EPD_MIN_REFRESH_MS`（默认 1200ms）
   就丢弃本帧，只保留最新缓冲。
2. **对话冻结**：Listening / Speaking 状态下不刷屏，只更新内存缓冲；回到 Idle 后补刷一次。
3. **定期全刷**：累计 60 次局刷或满 6 小时，插一次全刷清残影。全刷有明显黑白闪烁，
   所以固定低频，不做成每次刷新都全刷。
4. **差分同步**：每次局刷结束后，把同一帧同时写入控制器 `0x26`（上一帧缓冲）。
   SSD1683 的局刷靠 `0x24` 与 `0x26` 比较出差异，不写 `0x26` 会导致局刷不生效或花屏。

如果实测发现策略 1+2 之后体验仍然差，退化方案是：墨水屏只在待机时显示日历，
对话期间完全不参与显示。

## 6. 4.2 寸驱动要点

照 GxEPD2 的 `GDEY042T81` 时序实现，不沿用上游 2.9 寸的实现。

| 环节 | 4.2 寸 GDEY042T81 的做法 | 上游 2.9 寸的做法（不要照抄） |
|---|---|---|
| 初始化 | `0x12` 软复位 → `0x01` MUX=299 → `0x3C` 边框=`0x01` → `0x18` 温度传感器=`0x80` | 发 `0x0C` 软启动 / `0x2C` VCOM / `0x3A` / `0x3B` / `0x32` 自写 LUT |
| 全刷 | `0x21`=`0x40,0x00` → `0x22`=`0xF7` → `0x20` | `0x22`=`0xC4` → `0x20` |
| 快刷全屏 | 先写 `0x1A` 温度寄存器 `0x6E`，再 `0x22`=`0xD7` | 无 |
| 局刷 | `0x21`=`0x00,0x00` → `0x22`=`0xFC` → `0x20` | `0x22`=`0x04` → `0x20` |
| 差分缓冲 | 局刷后把同一帧补写 `0x26` | 完全不写 `0x26` |

时间常量（来源：GxEPD2 头文件实测值，单位毫秒）：
上电 100、掉电 300、全刷 1200、局刷 400。屏尺寸 400x300，帧缓冲每帧 `400*300/8 = 15000` 字节。

注意上游 `EpdDisplay` 的 `buffer_len` 由板级传入（2.9 寸板传 5000），这是按屏算的，
4.2 寸必须传 15000，多传少传都会越界或花屏。本项目因为重写驱动，改为常量派生，不手填。

## 7. 时间来源

板上没有 RTC，走 SNTP 联网对时（WiFi 已经常连），服务器用 `ntp.aliyun.com`。
断网期间靠系统时间继续走字，重新联网后自动校正。不新增 RTC 芯片。

## 8. 硬件待确认清单

以下信息只有卖家能给，缺一个都不能写死引脚。

1. 板型名称与购买链接。
2. 引脚定义图或原理图：I2S 五根线、I2C 两根线、PA 使能脚、BOOT 脚。
3. 板载音频 codec 型号（ES8311 / ES7210 / 其他），决定用哪个 codec 类。
4. 板载是否已有 OLED / LCD，分辨率与 I2C 地址。
5. Flash / PSRAM 容量确认（N16R8 应为 16MB + 8MB），决定分区表。

记录表见 `hardware/引脚记录表.md`。

## 9. 分阶段计划

### Phase A：不依赖硬件的部分（现在做）

- A1 装 ESP-IDF 6.1。
- A2 拉 `xiaozhi-esp32` v2.5.2 源码（当前最新正式 tag，`main` 上只有未发布的 2.5.3）。
- A3 写 4.2 寸 SSD1683 驱动 + 一个极小的点亮工程。
- A4 先编译上游 `maza-ai` 板型，验证工具链能出固件、能打包成 `merged-binary.bin`。
- A5 整理硬件待确认清单，发给卖家。

### Phase B：到货当天

- B1 确认板型与引脚，填 `config.h`。
- B2 用最小工程点亮墨水屏，验全刷 / 局刷 / 残影 / 实际耗时。
- B3 编自定义板固件，烧录，配网，绑 API Key，跑通第一次对话。
- B4 测刷新节流：对话时画面是否可接受。

验收：喊"小智小智"能对话；墨水屏显示时间且每分钟更新；对话时不被刷屏卡死。

### Phase C：联动（玩的部分）

- C1 日历页：时间 / 日期 / 星期 / 喝水进度，SNTP 对时。
- C2 到点播报喝水（本地 WAV，不依赖云端 TTS）。
- C3 语音记杯数："我喝了一杯" → 进度 +1 → 刷屏。

## 10. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 板型未知 | 引脚写不了，Phase B 卡住 | Phase A 先把所有不依赖引脚的事做完 |
| codec 不是 ES8311 | 板级初始化要改 | 等卖家确认；上游 70+ 板型里大概率有同款 codec 的现成类 |
| 面板 OTP 波形版本差异 | 快刷全屏 `0x1A`/`0xD7` 可能不生效 | 保留慢刷全屏 `0xF7` 作为兜底 |
| 墨水屏只有黑白两色 | 官方彩色表情 UI 在墨水屏上是黑白 | 已确认单色版；表情降级为黑白图标 |
| 全刷 1.2s 闪屏 | 定期全刷时会看到明显闪烁 | 全刷固定低频，可选放在夜间 |
| 新板型标识被 OTA 当作官方板 | 固件被覆盖回官方版本 | 板型标识必须唯一，控制台里关掉 OTA 自动升级 |
